做一个 Agent，最容易的部分可能是让它给出第一份看起来不错的回答。更难的是：它能否选对工具、根据真实材料推进、知道何时停下，并让别人核实它是否真的完成了任务。

这个系列不从模型训练或架构理论开始，而从一个应用问题开始：**如何把客户反馈变成有依据、可确认、不会重复提交的需求工单？**

这是贯穿系列的教学案例，不是一个实测产品。你可以把它替换成资料研究、客服处理、会议整理或其他业务任务，沿用设计与验证方法。

## 面向谁

- 开发人员：了解接口与一般软件开发，准备实现或改善一个 Agent 应用。
- 产品人员：有少量技术背景，需要定义功能、行为边界和验收标准。
- 已经使用 Agent 的团队：想区分“演示成功”与“可以持续交付”。

不要求了解模型训练、掌握某个 SDK，或先读本站的深度讨论文章。本系列独立成立。

四篇用八张 Mermaid 图解释行动循环、工具交互、授权状态、Skill 加载、失败排查、超时恢复、三层验证与持续改进。每张图只回答一个问题，图下注明它的边界。

## 系列的基本立场

1. Agent 不是所有任务的默认答案，固定流程够用时就先用固定流程。
2. Skill 提供方法，工具提供动作，授权决定本次允许做到哪里。
3. “说完成了”“接口报告成功”“实际结果正确”必须区分。
4. 出错先看输入、工具、状态与验收，不默认归因于模型。
5. 一个小任务端到端可靠，比一个巨大系统局部演示更有价值。

## 参考方式

每篇结尾保留官方来源与具体章节。资料主要来自 Anthropic、OpenAI 的公开工程指南、Agent Skills 开放规范，以及 LangChain 的评估清单；应用案例和清单是本文的教学归纳。

方法有适用范围，模型、工具和产品机制也会变化。本系列不提供绝对安全、生产成功率或跨框架无差别兼容的保证。
