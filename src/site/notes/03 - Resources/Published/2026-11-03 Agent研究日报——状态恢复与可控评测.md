## 今晚结论

**Agent 的新进展，不只在于模型能多做几步，还在于中断后能否恢复、结果能否公平比较。** 本期重点观察 Claude Message threads 和 WebHarbor；没有核到足以列为突发的证据。

业务日期为2026年11月3日，按中国时间21:00启动核查。以下区分发布日与本轮发现时间，不把旧更新写成今日首发。

## Claude Message threads：少传历史，仍要自己保留历史

11月2日官方更新宣布该功能进入Beta：服务端短期保存会话，后续请求只传新增消息。它降低的是重复传输和处理历史的负担；官方没有给出普适提速比例。[官方更新](https://platform.claude.com/docs/en/release-notes/overview)

技术文档明确：闲置五分钟会过期；应用须保留完整对话并支持回放。threads不自动缓存，也不改变定价；该功能不符合零数据保留条件。本轮未调用付费API测速。[技术文档](https://platform.claude.com/docs/en/build-with-claude/message-threads)

我的判断是，这项增量属于会话传输与恢复机制。比较接入前后的效果，应看完整任务耗时、恢复率与实际账单。一个建议的测试场景是：工具执行成功后连接中断，再恢复会话；既检查历史能否接回，也检查订单、邮件等现实动作是否会重复。这是待执行的测试设计，并非本轮实测。

## WebHarbor：把网页环境变成能重置的实验对象

论文v1提交于11月2日18:57 UTC，处于本期24小时窗口。作者提出153个容器化网站环境与3,518项任务，覆盖多步及登录后流程。训练迁移效果属于作者报告，本轮未复现。[论文与摘要](https://arxiv.org/abs/2611.03634)

仓库提供预构建镜像和启动说明，整套镜像约20GB，并提供环境重置接口；首次15站版本早在5月公开，所以本期应理解为扩充与正式论文发布。论文PDF提取失败，未完成全文精读。[官方仓库](https://github.com/aiming-lab/WebHarbor)

可控环境有助于比较同一任务的多次运行。它的局限也很清楚：镜像里成功，不能直接证明真实网站的登录、风控和最新页面也能成功。建议先挑一个网站验证状态重置，再固定任务与模型比较策略，最后另做真实站点的迁移检查。硬件耗时和运行成本本轮未知；没有下载安装或运行仓库代码。

## 其余观察与证据边界

HN上的Weight-Space Programming值得后续阅读。作者11月2日展示了直接检查或修改神经网络权重的实验，但不同实验允许的工具与反馈不同；其中一次辨认迎合模型的实验，仅凭权重失败，增加注意力观察后才成功。不能概括成模型已能任意理解或优化所有网络。本期仅观察，不据热度抬级。[作者原文](https://rikiyat.github.io/blog/weight-space-programming/)

GitHub Trending、HN、Product Hunt和arXiv三分类均只作有界发现；没有取得精确滚动星差与Release下载的完整对照，不认定爆款。其他厂商及中文圈没有补齐可用于本期重点的一手证据，这不表示没有更新。

## 两个值得继续验证的方向

1. **恢复是否安全。** 把“恢复了对话”和“没有重复现实动作”分别验证；先检查中断和回放，再评估速度收益。
2. **评测是否可重复。** 固定网页初始状态、任务与验收条件；把镜像内成绩和真实站点迁移分开报告。

本轮完成文档与公开入口核查，未实现代码、未运行模型实验；以上方向是研究建议。
