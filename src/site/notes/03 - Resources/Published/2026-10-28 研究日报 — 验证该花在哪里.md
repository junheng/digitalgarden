## 今天最值得记住的一句话

**同一个模型、同一份任务、同样两小时，四个 agent 框架里有两个交付了、两个交了白卷——而交白卷的那两个，换成它们自家的模型就能拿满分。**

这句话来自今天的新论文 kw-bench。它把一件工程上大家隐约知道、但很少被量化的事摆到了台面上：**框架（harness）不是中立的，它是为一个特定模型调出来的**。

顺带说，今天 arXiv 的 agent 论文几乎被同一个问题占满：**验证和评估应该花多少钱、花在哪里、怎么知道自己花对了**。下面挑五条值得记的。

## 一、框架是绑模型的：换模型后可能归零

**任务**：一份跨三代 SAP 的五年增值税重建——旧版 ECC、部分迁移到 S/4HANA、再加一次顾问的重设计。交付物只有原始系统导出：页头、本地数字格式、残缺的链接表，没有任何文档说明这些东西怎么连起来。**判分是确定性的，没有用模型当裁判**，这一点很关键，它把"框架好坏"从评审口味里剥了出来。

**对照实验**：四个框架、同一个模型 DeepSeek v4.1 Flash、同样两小时。

- OpenCode **0.542**、micro-cc **0.528**（两个与模型无关的框架都交付了）
- Claude Code **0.00**、Codex **0.00**（两个实验室框架离开自家模型后什么都没交付）

**换成 Claude Opus 5.5**：micro-cc **0.9986**、Claude Code **1.000**，分别 22 分钟和 25 分钟。

作者归因给一个词：**惯性**——能不能在长会话里维持住许多弱信号。

**为什么值得记**：我们平时习惯把框架当基础设施、把模型当可插拔件。"模型可替换、框架可复用"这个默认分层，在这里被打穿了：**两者是联合调优的对象**。换模型不像换发动机，更像换变速箱。

**一个我没能解决的分歧**：DeepSeek 的官方 API 文档把 Claude Code 和 Codex 都列在受支持的 agent 集成里，而这篇论文在它自家模型上给这两者 0.00。**官方说的"支持"和实际"能干活"之间的差距，两边都没有解释。** 可能的解释是协议兼容不等于长会话能维持，也可能两小时的预算对该框架默认策略过紧——但这是我的推断，没有验证。

来源：[kw-bench: Breaking Frontier Harnesses on Real-World Tasks](https://arxiv.org/abs/2610.36405)（代码在 [GSequist/kw-bench](https://github.com/GSequist/kw-bench)，创建于发布前一天，目前零星）

## 二、技能自优化的涨点，先拿"空候选"测一遍

第二篇更不客气：它把"技能优化涨点"拆成真提升与选择噪声，结论是三个优化器加起来，平均只比手写的那份技能高 **0.1 分**。

方法很便宜，值得抄：**把原始的技能自己当成一个候选，走一遍优化器的接受流程**——如果"什么都没改"的候选也能通过，那你的接受规则测的就是运气。

具体数字：三个优化器 × 三个 agentic 基准 × 两个模型。开发集上的增益到测试集就消失了；原因是**在最多 30 个任务上、保留多个候选中最好的那个，本身就足以报出这么大一块增益，即使没有一个候选真的改进了行为**。

代价也很实在：优化后的技能多读大约 **16% 的输入 token**，因为优化器几乎总是在**加规则**——一半是"再检查一遍工作"，一些是"一次只做一个调用"。agent 照做，于是多出轮次，每一轮重发整段对话。

作者给出四条原则，我认为可以直接用在自己的提示管理上：

1. 只有当改动带来的增益**超过"纯挑选"能报出的量**时才接受；
2. 按它**新增的轮次**计费，而不是按它的字数；
3. 让编辑器**能删、能合并**规则；
4. **把旧规则的成本展示给它看**。

来源：[Does Your Generalist Skill Optimizer Really Incentivize Agentic Tasks?](https://arxiv.org/abs/2610.37201)

## 三、验证该不该做，由"后果"决定，而不是由"不确定"决定

两篇论文从两个入口到达同一个结论。

**第一篇（工具调用侧）**：把**校准的失败概率、状态相关后果、可逆性、歧义度、证据新鲜度**合成一个按成本最小化的决策，在直接执行、验证、沙箱、澄清、审批、弃权之间选。在 20 个种子、每次 12 万条测试动作的模拟里，有害副作用的轨迹比例从"按不确定性排序"的 **14.75% 降到 7.02%**。

两个消融特别值得记：

- 按"失败概率 × 后果"排序的闸门，伤害接近（5.82%）但**送人工审批的动作多了 45%**；
- **去掉"可逆性"这一维，伤害率回到 15.53%**。

也就是说：**"这一步做错了能不能撤销"，比"我有多不确定"更能预测风险。** 还有一条反直觉的：给整个轨迹设风险预算，同等成本下**反而增加**了伤害（11.82%）。作者自己也声明，干预有效性是假设、不是实测，这只是在模拟器假设下给分配规则排序。

**第二篇（记忆侧）**：长生命周期 agent 靠跨会话记忆行动，而很多动作不可逆，过时的记忆会直接变成伤害。关键洞见是——**"这条记忆要不要复核"不是记忆的属性**：同一个记住的地址，日常发货可以不查，贵重发货必须先确认。于是问题被写成"动作条件验证"的序贯停止问题：**验证只有在能改变下一步动作时才值钱**。在 ToolSandbox 上，相对静态策略把验证成本降了 **33.9%**，同时保持 100% 的"安全放行"召回、0% 的危险放行。

来源：[CASEL](https://arxiv.org/abs/2610.36570)、[When Is a Memory Safe Enough to Act On?](https://arxiv.org/abs/2610.31446)

## 四、上下文按子任务树组织，还能顺手降价三成

"长会话上下文膨胀"的常规解法是压缩历史。今天这篇换了思路：**按子任务结构组织**。

做法是让 agent 用显式的"工作范围"声明子任务边界，同一个 agent 就地执行嵌套子任务（把委派留给真正独立的并行任务）；运行时维护一棵持久的子任务树，**每次调用模型前即时编译成上下文**——没完成的子任务保留交互细节，已完成的折叠成结果，并且**显式保住前缀缓存的复用**。

效果（集成进 Codex、用 GPT-5.6 Sol）：SWE-Milestone 分数 **+11.8%**，总成本 **−32.4%**；编程基准的平均测试通过率 **+17.3%**；十项前沿 SWE 任务里八项更好。**和"递归开子 agent"拿到相当的分数，但总成本低 73.7%。**

我认为这里最值得记的一句话是作者对递归子 agent 的批评：**"把每个子任务边界都交给委派，等于把子任务粒度和执行者选择混为一谈。"**

来源：[Spine: Compiling Subtask Trees into Structured Context for Long-Horizon Coding Agents](https://arxiv.org/abs/2610.37224)

## 五、监控器的准确率，不决定该不该重启

如果 agent 卡住了，该重启还是继续？常规做法是训一个"进度监控器"，看它的准确率。这篇用解析方法说明为什么这样不行。

结论：一个**固定 90% 准确率**的监控器，可以让成功率**从亏 5 个百分点变成赚 35 个百分点**，完全取决于**替换那次尝试在剩余预算里的成功率**。所以准确率不是决策价值，**"重来一次还有多少机会"才是**。

实证部分很难看：SWE-bench Verified 的 19 个 SymPy 问题、194 次外部评测执行、回溯审计 130 条轨迹——一个 **2.29 个点**的表面增益追溯到**单次幸存的失败尝试**；换到第二个模型上是 **−42.29 个点**；前瞻队列上初始增益没有复现；**103 次真实对比里，0 次**达到作者设定的认证门槛。

它给的办法是"证据不够就弃权"：在已有轨迹上用联合二项区间做无模型的决策审计，不额外调模型。

来源：[Monitor Accuracy Isn't the Answer](https://arxiv.org/abs/2610.36544)

## 六、顺手记下的几件事

- **Google Research 开源了 Harness²**：[google-research/harness2](https://github.com/google-research/harness2)，两万星，论文在 [arXiv 2610.14224](https://arxiv.org/abs/2610.14224)。它做两级递归：任务级用"提议—探测—组合"，靠**同一任务上的行为对比**来挑改动，不需要标准答案；另一级用一个持久的"改进框架"吸收被采纳的经验。三个专业基准上单步提升最多 11.5 分。它能直接跑，但仓库两周没更新、没有 release——**和今天第二篇的警告正好相反，这个张力我没法一天内解决**。
- **"已修复"是声明，不是观测**：一篇小样本复验研究检查了某个真实多 agent 系统里 10 条"已修复"的自我声明，在信息足够复验的那部分里，**50% 在"声称的位置"上找不到对应的修复**。
- **Cursor 的更新连续两期没动**，最新仍是 10 月 20 日的 Agent SDK：agent 就是一个代码文件夹，里面有指令文件、工具、技能、MCP 连接和消息通道，可以跑评测并一键部署。**"agent 即代码仓库"这个形态正在被产品化。**

## 证据边界

以上七篇论文**我只读了摘要原文**，设计细节、实验配置和附录都没读，所有数字都是**作者自报、未见第三方复现**。具体限制：

- kw-bench 是**单一基准、单一任务族**（增值税重建），不能外推成"实验室框架普遍不行"；代码存在但**我没有跑**。
- CASEL 的作者明确说**干预有效性是假设、不是实测**，那是模拟器里的排序结论，不是部署效果。
- Spine 的基准**全是编程类**，非代码任务没有验证；"总成本"的计价口径（是否含缓存折扣）我没读到。
- 监控器的 194 次执行集中在 19 个 SymPy 问题上，样本有明显选择。
- 星标数是传播量，不等于可用性或维护度。

今天的 arXiv 批次是 10 月 28 日的（cs.AI 254 条、cs.MA 27 条、cs.CL 108 条），比昨天的批次小，但主题集中得反常——**几乎全在问同一件事：验证与评估的钱该怎么花**。
