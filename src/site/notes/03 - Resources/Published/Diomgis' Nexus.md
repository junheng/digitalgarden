## 但请注意：这里的知识需要复核。

这个网站讨论的主题——Agentic Engineering、LLM 模型能力、Harness 设计——变化很快，部分工具和模型实践会以月为单位迭代。但**更新快，不等于所有知识都按同一个速度过期**。

今天适用的「最佳实践」，三个月后可能需要重测；六个月后，它的前提也可能因模型能力变化而消失。也可能它仍在承重。日期本身不能替你作这个判断。

这是实践笔记，不是有效期清单。新文章也会引用错误，旧文章也可能保留扎实的论据和有用的原则。

### 本站时效性公约

| 文章年龄 | 复核提示 | 建议 |
|----------|----------|------|
| 0 ~ 3 个月 | 刚写或刚修订，仍需核对 | 看来源、适用范围与验证方式，不把「新」当作「对」 |
| 3 ~ 6 个月 | 复查可能变化的前提 | 涉及模型能力、工具行为或 API 时，交叉核对当前版本 |
| 超过 6 个月 | 优先复核，而非自动判为过期 | 区分仍适用的原则、历史证据与需重测的实现，再决定是否用于决策 |

这里的月份是提醒复核的阅读约定，不是可信度评分，也不是领域的统一半衰期。文章标注的创建日期和最后更新日期，帮助你定位时间背景；**「updated」也不保证所有论点都已在最新环境下重新验证。**

复核时，最好把三个更新周期分开：

- **论据与原理**：看原始来源、推论边界和后续反证，不因年代久就自动失效。
- **API 与工具**：看版本、弃用信息和当前官方文档；实现细节可能比文章更新得更快。
- **任务与模型能力**：看当时的模型、配置、任务难度和验收标准；另一种任务上的进步，不自动证明当前任务可以撤掉支架。

### 本站在讨论什么

- **Agentic Engineering**：从「用 agent 写代码」到「设计 agent 系统」的工程化实践
- **Harness 设计**：prompt、工具、状态、权限与验证如何共同构成有效的运行环境
- **管线与脚本**：脚本既是工具，也可以是有明确数据契约和信任边界的管线节点
- **工程管理**：agent 对团队结构、招聘、组织的深层影响
